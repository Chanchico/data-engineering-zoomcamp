## 1: Notebook vs Script
   A script doens't need a jupyter server running. A script is easier to distribute because it can be run by Docker, cron or an orchestrator.
A script always runs from top to bottom, which makes it more reliable than a notebook, because notebook cells can be run independently and in any order, which creates hidden state.
## 2: `__name__` explanation
`__name__` is a global variable set by Python when the interpreter runs a Python module. When Python runs a script as the entry point, it automatically sets the script's `__name__` to `__main__`.

example code to visualise :

sandbox2.py
```python
def faah():
    print("in faah")
    print(__name__ == "__main__")

```
sandbox.py
```python
from sandbox2 import faah
print(type(__name__))
print(__name__ == "__main__")

faah()
```

`--target_table` parameter will write on the targeted table on the database.

Running this scritp with different parameters will break the idempotency of the ingestion, because it will write, for example, to another database, to another table orr different data. In contrast, running the script twice with the same arguments will preserve the idempotency of the ingestion.
 And the line that determines whether it is idempotent or not is: `df_chunk.to_sql(name=target_table, con=engine, if_exists="append")`.
